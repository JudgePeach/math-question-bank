# PDF 图文导入升级计划

## 目标与依据

在现有 PDF Inspector、PyMuPDF 与用户配置的识图模型上增加图文模式：提取原始配图，保留题干、选项、表格内的逻辑位置，提供原页证据和明确的待核对状态。默认不部署完整 MinerU，也不新增模型供应商。

参考 MinerU 的方法，而非声称接入其模型：

- [MinerU2.5 论文](https://arxiv.org/abs/2509.22186)：全页布局分析与原分辨率局部处理分离。
- [官方输出结构](https://opendatalab.github.io/MinerU/reference/output_files/)：页号、区域、阅读顺序及图片资产保留在结构化中间结果中。
- [当前运行档位](https://opendatalab.github.io/MinerU/usage/tiers/)：完整识别运行时与本项目现有轻量部署分开考虑。

引用的 ChatGPT 讨论在本次任务中两次读取失败；本计划以本任务讨论、当前代码及上述公开一手资料为依据。用户随后明确选择“优先沿用现有模型与本地程序，借鉴 MinerU 的流程”。

## 实施顺序

1. **页级结构与提图**：记录原 PDF 页号、渲染坐标、文字区域、位图/矢量候选；统一旋转页与 CropBox 的坐标。配图按确认的区域从原 PDF 渲染，保留线条、标注、遮罩和组合图的实际外观。
2. **视觉布局判断**：在含图、疑似图及 OCR 页中，一页一次调用现有识图模型。输入整页、候选框与已提取原文，输出配图区域及原文前后锚点；不要求重写已提取公式。限制输入、区域数量、输出和请求时间，不自动付费重试。
3. **保守归位与来源核对**：只有唯一、精确且不落在公式或代码内部的锚点才能插图；表格及选项内位置保留。错误坐标、遗漏候选、无法归位的图、模型失败均保留证据并提示核对。先检查 PDF→图文原文，再使用已有 Word/TeX 来源核对检查图文原文→题目卡片。
4. **产品接入与验证**：新增默认“智能图文提取”，保留“文字优先”和“全页识图”。老客户端未传策略时保持旧行为；非法策略拒绝。显示真实提图、归位、视觉请求及待核对数量。自动解答/入库不得绕过已有教师确认。

## 资源与兼容边界

- 本轮不更改数据库结构、用户模型配置或版本号，不进行打包、Git 推送或公网发布。
- 图片使用任务临时目录，创建后立即登记；取消、失败、TTL 回收和入库晋升沿用现有任务/资产规则。
- 保留选择页范围及原页编号；不把跨页当作题目边界。
- 不用整页文字相似度给题目猜配图片，不凭模型自报 confidence 自动放行。
- 图内文字与正文重复、扫描页 OCR 的原文误识别仍需核对；图片引用和数量一致不等于内容及归属绝对正确。
- 完整 MinerU 本地服务或官方解析 API 可另作独立适配，当前阶段无需新增其依赖或凭据。

## 原生文字与局部识别优化

针对“可复制文字的转换卷为何仍整页OCR”的反馈，新增保守区域流程，并修正两个质量判据：位置提取API的一基页码转换，以及将普通图片总数误作公式缺失证据。武汉第2页仍有真实跨题伪表格，修正计数后由其具体错排证据继续保护，不能直接放行该Markdown。

文字优先、智能图文在原生坏页上先尝试本地几何规划：仅保留完整可靠中文行，公式、数字、变量、上下标、图中文字及可见细分数线保留在完整风险区域；同页最多3个裁片只发一次模型请求。大空白可在区域预算内去除。智能图文同时定位配图，区域坐标映射回原页并重新绑定占位，后续不再追加一次布局请求；文字优先只转录并保留手动配图。全页识图保持原行为。付费区域请求失败不会自动再发整页请求。
