## 一、实施原则

本次整理采用“入口稳定、业务下沉、工具归类、数据不迁移”的低风险策略：

1. 根目录 `main.py` 继续作为 `uvicorn main:app` 入口，双击启动方式保持不变。
2. 正在使用的 `math_question_bank.db` 继续保留在根目录，避免旧版升级与 Release 数据迁移风险。
3. 后端领域模块统一收敛到已有的 `mathbank/`，不再新建重复的 `core/` 包。
4. 运维、迁移、检索和打包工具统一收敛到 `scripts/`。
5. 所有持久化与资源路径继续由 `mathbank.paths` 锚定 `PROJECT_ROOT`。
6. 历史数据库和测试产物只归档、不删除。

## 四、标准命令

从项目根目录运行：

```bash
# 启动服务
python3 -m uvicorn main:app --reload

# 检索题库
python3 -m scripts.search_questions -q "导数"

# 数据迁移
python3 -m scripts.migrate_fillin
python3 -m scripts.migrate_choice_parentheses

# 构建 Release
python3 -m scripts.build_release

# 自动化测试
PYTHONPATH=. pytest -q
```

## 五、兼容性与后续方向

- `main.py`、启动器和主数据库位置不变，因此日常使用方式不变。
- Python 文件换目录只改变源码组织，不会增加可感知的运行负担。
- Git 可依据内容相似度识别文件重命名，历史可通过 `git log --follow mathbank/paper_helper.py` 查询。
- Release 用户仍可通过复制旧版 `.env` 与 `math_question_bank.db` 完成升级。
- 后续若继续缩减 `main.py`，应优先按业务域建立 `mathbank/routes/` 与 `mathbank/services/`，并逐模块提交和回归测试，不再进行大规模一次性迁移。
